## ما نُفّذ

1. تنزيل APK عبر HTTPS وتسجيل بصمته دون تشغيله أو تحميل مكتباته داخل عملية التحليل.
2. التحقق من مسارات الأرشيف وحجمه، ثم جرد محتوياته وفحص البيان والتوقيع.
3. تحليل ELF لكل مكتبات `.so` المعبأة: المعمارية، الاعتماديات، الرموز المصدّرة
   والمستوردة، Build ID عند توفره، وجود رموز التصحيح، ومقاطع تفكيك محدودة لدوال مختارة.
4. مقارنة المكتبات المتناظرة حسب الاسم والمعمارية، ببصمة الملف الكامل وبصمة قسم `.text`.
5. فك Java والموارد باستخدام JADX 1.5.3، وفهرسة JNI وتحميل المكتبات والتهيئة.
6. استخراج سياق تمرير صيغة الصور إلى native وواجهات التحكم بأزرار GTA.

هذا **تحليل بنيوي ومقارنة مستهدفة**، وليس استعادة كاملة لكود C++ أو تدقيقًا لكل
تعليمة ومسار تشغيل. لم تُشغّل اللعبة أو تُختبر عملية spawn في هذا التحليل.

## النتائج المهمة

وجدنا **29 مكتبة native**، مع وجود `libsamp.so` و`libGTASA.so` لكل من
`arm64-v8a` و`armeabi-v7a`. إذن APK ليس مجرد واجهة تنزيل خالية من عميل اللعبة.
وجود المعماريتين لا يثبت أنه يعمل على كل هاتف أو تعريف رسومي.

| المكتبة | النتيجة |
|---|---|
| libGTASA، المعماريتان | الملفات الكاملة مختلفة؛ قسم `.text` مطابق؛ عناوين 64 دالة مختارة متطابقة من أصل 64 |
| OpenAL32 / OpenAL64 | الملفات مختلفة؛ قسم `.text` مطابق |
| SCAnd، المعماريتان | الملفات مختلفة؛ قسم `.text` مطابق |
| ImmEmulatorJ، 32-bit | الملف مختلف؛ قسم `.text` مطابق |
| LuaJIT، المعماريتان | الملفات الكاملة مطابقة |
| monetloader، المعماريتان | قسم `.text` مختلف |
| libsamp، المرجع مقابل build-91 | قسم `.text` مختلف على المعماريتين |

**الاستنتاج المحدود:** حجم المكتبة وبصمتها الكاملة وحدهما لا يثبتان اختلاف كود
المحرك. لا يوجد أساس لاستبدال libGTASA عشوائيًا على أنه «محرك آخر يصلح الكراش».
تطابق `.text` لا يعني تطابق كل البيانات والتهيئة أو التعديلات التي تطبقها hooks
وقت التشغيل، ولا يثبت توافق كل المكتبات الإضافية.

### مسار GPU — تصحيح مهم

في Java المفكوك، `SAMP.java` يستدعي
`setGpuTextureFormat(Util.getStoredGpuType(this))`.
لكن `Util.detectGpuType` يسجل امتدادات GL، ثم يثبت `GPU="dxt"` ويخزن القيمة `1`
ويعيد `1` بغض النظر عن الامتدادات المسجلة.

هذه الملاحظة تمنع الاستنتاج الخاطئ بأن المرجع يختار PVR تلقائيًا لهذا الهاتف.
لم نُكمل تتبع تنفيذ المحدد الأصلي أو تحويل/رفع الصور إلى GPU؛ واجهة JNI نفسها
مجرد تحويل وسيط وقفزة إلى دالة أخرى. لا يجوز استنتاج عدم وجود تحويل برمجي من ذلك.

### واجهات غير موجودة في صادرات العميل المحلي المقارن

المرجع يصدر واجهات JNI منها:
- setGpuTextureFormat وreleaseLatchedInput وinitializeMonet.
- nativeReadWidget وnativeUpdateWidget وnativeResetWidgets وnativeResetSampWidget.
- واجهات Java لشريط الأزرار والشات وإعدادات اللعبة والإيقاف المؤقت.

هذه أسماء ومسارات مقارنة، وليست دليلًا أن غياب كل واحدة يسبب الكراش. ولا تثبت
عدم وجود وظيفة مشابهة في المشروع بواجهة مختلفة. أزرار GTA منفصلة عن `>> / <<`.

## جودة فك Java

JADX وصل إلى نهاية المعالجة، لكنه أنهى العمل بخروج `1` و**خمسة أخطاء**.
الأثر يحتوي السجل والمخرجات الجزئية. نجاح job يعني اكتمال إجراءات التحليل
وحفظ الأدلة، **ولا يعني نجاح فك كل الطرق** أو ضمان صحة Java الناتج.

## ماذا تغير في المشروع؟

أُضيفت أدوات التحليل وworkflow واختبارات سلامة الأرشيف فقط. لم تُستبدل مكتبات
اللعبة، ولم يُنسخ كود المرجع إلى التطبيق، ولم تتغير الأزرار أو الأنيميشن أو مسار
التحميل. لا يوجد APK إصلاح جديد ناتج عن هذا العمل.

## العمل المتبقي قبل إصلاح مستند إلى المقارنة

1. تحديد الدوال في crash-7 باستخدام الرموز المطابقة تمامًا لإصدار المستخدم.
2. تتبع تنفيذ صيغة GPU والتحويل/الرفع والـRLE داخل العميل المرجعي، لا مجرد أسماء JNI.
3. مقارنة عمر الموارد والـhooks في مسارات الرسم والتحميل ذات الصلة بالأعطال،
   مع مراجعة اختلاف monetloader دون افتراض أنه السبب.
4. تصميم إصلاح مستقل صغير يمكن اختباره ضد الحالة المعيبة؛ عدم نقل binary أو
   كود طرف ثالث دون صلاحية وتحقق من التوافق.
5. اختبار التشغيل وspawn وrespawn والخروج والدخول المتكرر على الجهاز؛ نجاح
   CI أو التحليل الساكن لا يثبت استقرارًا بنسبة 100٪.

**الحالة:** التحليل الأولي أنجز وأنتج فروقًا محددة. السبب الجذري المتبقي للكراش
لم يثبت من هذه المقارنة وحدها، ولم يُدّعَ إصلاحه.

## استكمال التحليل الأصلي وإصلاح قابل لإعادة الاختبار

- التحقيق الأصلي: [41199317872](https://github.com/mehdigm4life/GS-SAMP-Mobile/actions/runs/41199317872).
- تحقق تطابق `.text` لرموز build-91 مع APK المنشور:
  `804e8701479da7c99d53e5bdf8ade61c39562d04f0b80b56cb441421ebb8fb74`.
- crash-7: العنوان `0x1e81b0` داخل `CObjectPool::Delete`، والاستدعاء
  `0x1edfe4` داخل `ScrDestroyObject`. العطل الآخر `0x1e9fd8` داخل
  `CPlayerPool::ProcessAttachedObjects`. كلا العطلين يقرأ عبر مؤشر pool غير صالح؛
  هذا يحدد موضع ظهور التلف، لا الكاتب الذي سببه.
- سلسلة JNI → PLT → relocation وصلت إلى
  `TextureDatabaseRuntime::SetFormatFromLauncher` عند `0x1a3404` في المرجع.
  الدالة تخزن القيمة **1**، وليست اختياراً تلقائياً لصيغة خاصة ببطاقة الهاتف.
- المرجع يملك `DecompressTXDBRLE` بوسيط طول مصدر مستقل، بينما hook المشروع
  يعتمد على حجم آخر طلب `OS_FileRead` العام. هذا اختلاف مؤكد يحتاج إصلاحاً
  على مستوى مالك مخزن البيانات، وليس تخمين حجم المصدر من حجم الوجهة.
  لا ننسخ المفكك المرجعي: فالتفكيك يظهر نسخ مقطع كامل عند النهاية، ولا يثبت
  أن الدالة آمنة لكل طول وجهة أو أنها سبب أعطال الهاتف.

### إصلاح map-icon المنفذ

`m_dwMapIcon` يضم 100 خانة، بينما معرف الشبكة يسمح بـ256 قيمة.
كانت دالتا الإضافة والإزالة تستخدمانه قبل أي تحقق، والمؤشر `m_pPools`
يأتي بعد المصفوفة في تعريف `CNetGame`. الإصلاح يرفض 100..255 قبل الفهرسة،
ويرفض رسائل RPC الناقصة والمؤشرات الفارغة. كذلك أُصلح الخلط بين معرف
الخانة ونوع أيقونة GTA: تبديل النوع الاحتياطي لا يغيّر معرف الخانة.

الاختبار `tests/test_map_icon_safety.py` يشغّل الدوال الإنتاجية المستخرجة
مع بدائل بسيطة للمحرك وقارئ الرسائل، تحت ASan/UBSan:

- `python3 tests/test_map_icon_safety.py 81411cd` يفشل في الكود السابق:
  `index 100 out of bounds for type 'unsigned int [100]'`.
- `python3 tests/test_map_icon_safety.py` ينجح بعد الإصلاح: جميع القيم
  100..255، الخانات السليمة، الرسائل الناقصة، والحارس المجاور للمصفوفة.
- اختبارات SCM، عمر المواد، مالك تقرير الانهيار، وtextdraw نجحت محلياً أيضاً.
- الاختبار مضاف إلى بوابة بناء Android.

**الحدود:** لم يثبت أن السيرفر أرسل معرفاً خارج النطاق أثناء crash-7؛
هذا إصلاح لتجاوز مثبت، وليس ادعاء إثبات السبب الجذري لذلك السجل.
تحقق Android بدأ في [41199322830](https://github.com/mehdigm4life/GS-SAMP-Mobile/actions/runs/41199322830).
لا يحل هذا التغيير مشكلة Widgets الأصلية ولا يغيّر الميكروفون أو الأنيميشن أو أزرار الإظهار والإخفاء.
